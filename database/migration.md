# DB 마이그레이션

## 개념
데이터를 하나의 데이터베이스에서 다른 데이터 베이스로 이동시키는 전체 과정을 의미

## 마이그레이션을 하는 이유
1. 시스템 업그레이드: 구버전 DB엔진을 최신 버전으로 업데이트할 때
2. 인프라 이전: 사내 서버에 있던 DB를 AWS. Google Cloud 같은 클라우드 환경으로 옮길 때
3. DB 엔진 변경 : 비용 절감이나 성능 향상을 위해 (ex: Oracle -> PostgreSQL)
4. 데이터 통합 및 분할: 여러 개로 흩어진 DB를 하나로 합치거나, 너무 커진 DB를 쪼갤 때

## 마이그레이션 단계
1. 계획 및 분석: 데이터, 용량, 서비스 중단시간 정의
2. 스키마 변환: 테이블 구조, 데이터 타입, 함수 등을 새 DB에 맞게 변환
3. 테스트 전환: 실제 데이터를 옮기기 전, 일부 데이터(또는 복사본)로 마이그레이션을 시뮬레이션하여 오류를 잡아냄
4. 데이터 추출 및 로드: 데이터 전송
5. 정합성 검증: 데이터 유실 확인 및 데이터 값 확인
6. 컷오버: 새 DB로 연결 전환

## 마이그레이션 방식
### 빅뱅 마이그레이션
서비스 중단(점검화면 띄움)하고 한 번에 모든 데이터를 새 DB로 옮긴 후 서비스 실행

장점: 구조가 단순하고 데이터 정합성을 맞추기 쉽습니다.<br/>
단점: 데이터 양이 많으면 서비스 중단 시간(다운타임)이 길어집니다. 24시간 중단되면 안 되는 서비스에는 치명적입니다.
### 단계적 마이그레이션
서비스를 계속 운영하면서 뒤에서 기존 DB와 새 DB를 동기화시킴. 데이터가 실시간으로 양쪽에 다 쌓이게 만든 후, 준비가 되면 새 DB로 전환

장점: 서비스 중단 시간이 거의 없거나 몇 초 내외로 매우 짧습니다. <br/>
단점: 시스템 구성이 매우 복잡하고 비용이 많이 듭니다.

## 마이그레이션 필수 체크 리스트
1. 백업
2. 데이터 오염 방지
3. 보안 및 권한
